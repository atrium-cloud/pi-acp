Per-host origin overrides for Pi's provider requests through `PI_ACP_ORIGIN_OVERRIDES`. For Pi 1.3.0 and above.

## Added

- `PI_ACP_ORIGIN_OVERRIDES` sends Pi's https requests for a listed host to another origin; off when unset.
    - Entries are comma-separated `<authority>=<origin>` pairs, for example `opencode.ai=http://127.0.0.1:3129`.
    - `<authority>` is the lowercase host, with a `:port` only for a port other than 443.
    - `<origin>` is `scheme://host[:port]` alone, with an `http` or `https` scheme.
    - A matched request keeps its own path, query and headers, so one entry covers every model behind that host, whatever wire each uses.
    - A malformed or repeated entry fails startup.
    - Requests Pi sends before a session's first provider call, such as a model catalog refresh, still go to the provider's own host.

## Compatibility

- Pi releases below 1.3.0 are not verified; the dependency floor moved to `>=1.3.0`.
- Pi 1.3.0 changes what a client sees through the adapter:
    - Switching the `model` option drops the earlier model's thinking instead of sending it to the new model as plain text.
    - A session reopened from its file (`session/load`, `session/resume`, `session/fork`, an idle wake) keeps the tools activated during it.
    - A tool call whose arguments are malformed JSON fails validation instead of running with the fields parsed so far.
    - OpenCode Zen and Go requests use `https://opencode.ai/inference` paths on the same host.
- With `PI_ACP_ORIGIN_OVERRIDES` unset, Pi's requests go where they did in prior releases.
