MCP through Pi's own built-in support, argument hints on slash commands, and `PI_ACP_HIDE_COMMANDS`. For Pi 0.99.1 and above.

## Added

- A prompt template's frontmatter `argument-hint` is advertised as the command's `input.hint`.
    - Pi's `get_commands` drops the hint, so it is re-read from the template file with Pi's own frontmatter rule.
    - A failed read or parse costs that command its hint only, with one stderr line.
    - Skills and extension commands get none, since Pi has none for them.
    - `/name` carries `<name>`; `/session` and `/compact` carry none.
- `PI_ACP_HIDE_COMMANDS`: a comma-separated list of command names left out of `available_commands_update`.
    - Pi 0.99 loads its built-in extensions in RPC mode, so their commands `/mcp` and `/llama` reach the client's menu like any extension command; this hides them.
    - The adapter's own `/name`, `/session` and `/compact` can be hidden the same way.
    - A hidden command a client sends anyway still runs.

## Changed

- MCP servers are served by Pi 0.99's built-in MCP support. The adapter's own bundled MCP client is gone.
    - Each `mcpServers` entry is translated to Pi's server config and registered through `pi.registerMcpServer` by a small extension a session loads only when its request carries servers.
    - Tools are still `mcp__<server>__<tool>`, declared to the model directly (`exposure: "direct"`), not behind Pi's default `codemode` sandbox tool.
    - Every MCP tool still goes through the permission gate.
    - Pi interpolates `env` and `headers` values (`$NAME`, `${NAME}`, a leading `!cmd`); the adapter escapes each value, so it reaches the server verbatim.
    - A stdio server runs in the session cwd and inherits the whole Pi process environment plus its own `env`. The safe-list environment of prior releases is gone.
    - Pi owns protocol negotiation, result mapping, `isError` results, `tools/list_changed`, reconnects and resources.
    - Result text over 20 KB is middle-truncated by Pi, with the full text in a temp file; the adapter's 50 KiB / 2000-line bound is gone.
    - A server that fails to connect is reported by Pi as one `warning` notice, in Pi's wording, once the startup connections settle; the adapter's `MCP server <name> failed:` line is gone.
    - The first prompt waits up to 10 s for servers still connecting; a slower server's tools appear once it connects.
    - Rejected with `invalid_params`, alongside the existing duplicate-name, `acp` and unparseable-url cases: a name outside `[A-Za-z0-9_-]`, the `sse` transport (the message points at streamable HTTP), and a url that is not http or https.
- Whether a prompt started a turn is read from Pi's `prompt` ack `disposition`, not from a quiet window.
    - `handled` (an extension command or input handler consumed the prompt) ends `end_turn` at once. Prior releases waited 10 s for an advertised extension command and raised an internal error for any other prompt that started no turn.
    - `started` with no `agent_start` within 10 s stays an internal error, with new wording.
    - `queued` is an internal error, since the adapter never sends a second prompt while one streams.
    - A cancel that lands during the ack still wins as `cancelled`.
- A breakpoint message id is recorded once Pi reports the turn's user message, no longer gated on the session file already existing.
    - A prompt cancelled before that report echoes no id.

## Fixed

- A first turn that ended before Pi wrote the session file could not record its breakpoint message id. Pi 0.99 writes the file at the first user message, so the id is recorded.

## Compatibility

- Pi releases below 0.99.1 are not verified. The dependency floor moved to `>=0.99.1`, since the adapter relies on the `prompt` disposition and the built-in MCP support.
- `initialize` advertises `mcpCapabilities.sse: false`. A client that sends an `sse` server fails `session/new` with `invalid_params`; prior releases served it.
- Pi's own `~/.pi/agent/mcp.json` servers connect in every session alongside the client's.
    - An entry with the same name as a client-supplied server overrides it, and nothing on the wire reports the override.
    - A `.pi/mcp.json` in the cwd needs project trust, which RPC mode cannot prompt for.
    - `"extensions": ["-builtin:mcp"]` in Pi's settings turns the built-in support off entirely, client servers included.
- Pi authenticates an HTTP server without an `Authorization` header through OAuth, whose sign-in dialog the adapter cancels, so a client-supplied HTTP server has to carry its credentials in `headers`.
- Pi 0.99.0 and 0.99.1 change what a client sees through the adapter:
    - A session whose first turn started and was then cancelled or failed has a file, so it is listable, resumable, forkable and deletable. Before, only a session with an assistant message was.
    - `/mcp` and `/llama` are advertised unless hidden. `/mcp` answers through `ctx.ui.notify`, so only a client that advertises `session.notices` sees its output.
    - A tool that calls other tools (Pi's `codemode`, when a Pi setting or the user's `mcp.json` activates it) emits nested calls with ids of the form `<parent>/<n>`; a client sees them as flat sibling tool calls, and `session/load` replays the parent call only. The permission gate prompts for a nested mutating or MCP call as for a top-level one.
- Built on ACP SDK 1.5.1, which caps one incoming message at 32 MiB by default; a larger one ends the connection, and the adapter exits.
