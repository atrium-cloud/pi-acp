The origin overrides cover Pi's model catalog refresh, and each adapter process writes its Pi extensions into a temp directory of its own. For Pi 1.3.0 and above.

## Changed

- `PI_ACP_ORIGIN_OVERRIDES` covers Pi's model catalog refresh: the extension wraps Pi's HTTP dispatcher again at `session_start`, as well as before each provider call.
    - OpenRouter's `/models/user` read, which narrows Pi's saved catalog to the models the key may use, goes to the override origin; prior releases sent it to `openrouter.ai`.
    - A request Pi starts before `session_start`, such as an early `pi.dev` catalog fetch, goes to its own host.

## Fixed

- Each adapter process writes its Pi extensions into its own `mkdtemp` directory, removed when that process exits.
    - Prior releases named the directory after the process id, so adapters sharing a pid, as every sandboxed adapter is pid 1, shared one directory, and the first to exit removed the extensions of the others.
