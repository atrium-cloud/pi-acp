A model catalog refresher keeps Pi's saved model list current, the origin overrides cover Pi's model catalog refresh, and each adapter process writes its Pi extensions into a temp directory of its own. For Pi 1.3.0 and above.

## Added

- The adapter refreshes Pi's model catalog in a Pi subprocess of its own, 60 s after it starts and hourly after that.
    - Pi saves the refreshed catalog to its `models-store.json`, which every Pi started afterward restores, so a later `session/new` offers the current models.
    - The subprocess runs with `--no-session --offline --no-mcp` and loads the extensions every session loads, the origin overrides included, plus a refresh extension that only it loads, so no session advertises the refresh command.
    - Each refresh asks Pi for a network refresh of every provider's catalog, bounded at 15 s.
    - One refresh runs at a time per adapter process. A failed one is logged to stderr as one line, and the catalog Pi saved last keeps serving.
    - An adapter process stopped within 60 s of starting, such as one a client starts only to read the model list, runs none.
    - After a host suspend longer than an hour, the overdue refresh runs once on resume.

## Changed

- `PI_ACP_ORIGIN_OVERRIDES` covers Pi's model catalog refresh: the extension wraps Pi's HTTP dispatcher again at `session_start`, as well as before each provider call.
    - OpenRouter's `/models/user` read, which narrows Pi's saved catalog to the models the key may use, goes to the override origin; prior releases sent it to `openrouter.ai`.
    - A request Pi starts before `session_start`, such as an early `pi.dev` catalog fetch, goes to its own host.

## Fixed

- Each adapter process writes its Pi extensions into its own `mkdtemp` directory, removed when that process exits.
    - Prior releases named the directory after the process id, so adapters sharing a pid, as every sandboxed adapter is pid 1, shared one directory, and the first to exit removed the extensions of the others.
