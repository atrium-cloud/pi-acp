Breakpoint forks from an earlier prompt, Pi's TUI built-ins `/name`, `/session` and `/compact`, and session notices. For Pi 0.87.1 and above.

## Added

- Breakpoint forks: `session/fork` can cut just before an earlier prompt the client names.
    - `initialize` advertises it as `sessionCapabilities.fork._meta.acpStack.messageId`, an empty object.
    - A client tags a `session/prompt` with `_meta.acpStack.messageId`, an id it mints itself.
    - The prompt response echoes the id under the same keys once it is recorded.
    - No echo means the prompt cannot be forked from.
    - Nothing is recorded for a built-in, an extension command that starts no turn, a prompt cancelled before it reached Pi, or a session Pi does not persist.
    - A prompt cancelled after its turn started is still recorded.
    - A failed record costs only the echo; the turn still settles, and one stderr line names the failure.
    - A first turn that ended before Pi wrote the session file fails to record this way.
    - `session/fork` carrying the same `_meta` keeps the named prompt's ancestors, the prompt itself excluded.
    - Entries off that path, such as abandoned branches, are dropped, unlike in a head-only fork.
    - Naming the first prompt forks to a session with no conversation.
    - An id that was never recorded, or that maps to an entry that is not a user message, is `invalid_params`.
    - Without the `_meta`, `session/fork` is head-only as before.
- The id map is a sidecar `<stem>.acp.json` beside Pi's `<stem>.jsonl`: `{ "version": 1, "messages": { "<message id>": "<Pi entry id>" } }`.
    - A resumed or forked session extends the map it inherits.
    - A fork keeps only the ids whose entries it kept, head-only forks included.
    - `session/delete` removes it with the session file.
- Pi's TUI built-ins `/name`, `/session` and `/compact` run over their Pi RPC equivalents.
    - `available_commands_update` lists them first, with Pi's own descriptions and no `input`.
    - Each replies with one `agent_message_chunk`, worded as the TUI words it, and ends `end_turn`.
    - A bare `/name` shows the current name, or the usage line when there is none.
    - `/name <name>` sets the name, reports the name Pi stored, and sends a `session_info_update`.
    - A session named with `/name` is not retitled from its first prompt.
    - `/session` mirrors the TUI report, minus the TUI's cache-warming diagnostics, the per-model cost breakdown, and cache re-billing.
    - `/compact [instructions]` reports the token count it compacted from and sends a `usage_update`.
    - A Pi refusal to compact is agent text, and nothing is written.
    - A cancelled `/compact` answers `cancelled`; Pi stops the compaction unless it has already written it.
    - `/compact` has no timeout.
    - A running built-in holds the session like a turn, so a second prompt is refused.
    - No title is derived and no breakpoint id is echoed, since Pi appends no user entry for a built-in.
- A `tool_call` carries Pi's tool name as `name`, live and in `session/load` replay; `tool_call_update` leaves it out.
- An extension's `ctx.ui.notify` reaches a client that advertises `clientCapabilities.session.notices` as a `notice` session update.
    - `severity` is Pi's notify type, `info` when it names none.
    - `title` is the message; a blank message is not forwarded.
    - A notify during session setup follows the first `available_commands_update`.
    - Notices are live only; `session/load` replays none.
    - The stderr line every notify already wrote stays.
- An MCP server that fails to start is also reported as a `warning` notify.
    - The message is `MCP server <name> failed: <error>`, on one line, without the server's stderr tail.
    - Failures are reported in the order the servers were listed.

## Changed

- A prompt whose trimmed text invokes `/name`, `/session` or `/compact` no longer reaches Pi's `prompt`. Prior releases sent it to the model as text.
- A Pi command named `name`, `session` or `compact` is no longer advertised; the built-in shadows it, as in the TUI.
- A replayed tool result's `rawOutput` no longer carries `addedToolNames`, including in sessions that earlier Pi releases recorded with it.

## Fixed

- An `sse` MCP server received every client header twice on its event stream request, so a server that checks `Authorization` refused the stream.
- A head-only fork of a session with a turn in flight could drop the session's last settled turn.
    - The fork now leaves out only the running turn, from Pi reporting its user message until it settles.
    - Before that report, as in a preflight compaction or an extension command that starts no turn, the fork copies every entry.
    - After the turn settles, the fork copies every entry.

## Compatibility

- Pi releases below 0.87.1 are not verified.
- Pi 0.86.0 and 0.87.0 change what a client sees through the adapter:
    - A `bash` command killed by a signal ends `failed` with `exit_code` 1, where it used to end `completed` with 0.
    - Pi's `Command terminated without an exit code` line stays in that command's terminal data.
    - `usage_update` cost includes Pi's prompt-cache warming refreshes; Pi's `cacheWarming` setting defaults to `streaming`.
    - `/session` token and cost totals include the same refreshes.
    - The `/session` message total counts Pi's `system` messages, so it can exceed user, assistant and tool results combined.
    - `session/load` replay leaves out messages Pi has edited out of the model context, such as abandoned retry attempts.
- Built on ACP SDK 1.5.0, whose schema adds `ToolCall.name` and the experimental `notice` update.
- Notices are experimental in ACP v1; a client that does not advertise `session.notices` gets none.
- A client that sends no `_meta.acpStack.messageId` is unaffected: forks stay head-only, and prompt responses carry no `_meta`.
- Pi's session store gains `.acp.json` files; neither Pi's session scanner nor the adapter's lists them.
- The sidecar assumes one adapter process per session store; two processes can overwrite each other's maps.
