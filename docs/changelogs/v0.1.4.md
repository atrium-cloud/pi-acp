Per-turn token usage on the prompt response. For Pi 0.87.1 and above.

## Added

- A `session/prompt` response carries `usage`: the tokens its turn used, cache reads and writes included.
    - The numbers are the turn's share of Pi's session totals, read just before the turn starts and again once it settles.
    - They count everything Pi records during the turn: model responses, tool results, auto-compaction and cache-warming refreshes.
    - `cachedReadTokens` and `cachedWriteTokens` are always sent.
    - `thoughtTokens` is never sent, since Pi's totals carry no reasoning count.
    - A turn that started carries usage whatever its stop reason, `cancelled` included.
    - `/compact` carries the compaction's usage when Pi completes it.
    - A compaction Pi refuses or aborts carries none, since Pi records none.
    - `/name`, `/session`, an extension command that starts no turn, a prompt cancelled before it reached Pi and a turn cut short by `session/close` carry none.
    - If either read of Pi's totals fails, `usage` is left out and one stderr line names the failure; the turn still settles.

## Compatibility

- Pi releases below 0.87.1 are not verified.
- `PromptResponse.usage` is experimental in ACP v1.
- The numbers are per turn, as the schema's `usage` field says.
    - The `Usage` type's own field docs describe session-wide totals; a client that follows them will misread these numbers as cumulative.
