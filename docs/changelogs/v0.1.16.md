A client forks at an earlier prompt through ACP session cursors, which replace the `_meta.acpStack.messageId` breakpoint. For Pi 1.6.1 and above.

## Added

- Session cursors (unstable, Session Cursors RFD), sent to a client that advertises `clientCapabilities.session.cursors`.
    - A `cursor_update` announces one cursor before a user message, with `capabilities.fork`.
    - A `session/load` replay sends each user message with a `messageId`, then its cursor anchored `before` that message.
    - A live prompt's cursor arrives once its turn settles, anchored `after` the last message or tool call the client holds.
    - Agent message and thought chunks carry a `messageId`.
- `session/fork` takes a `cursorId` and copies the history before that cursor's prompt.
    - A `cursorId` that names no prompt on the session's current branch is refused with `invalid_params`.
    - A cursor id holds across connections and adapter restarts.

## Removed

- The `_meta.acpStack.messageId` breakpoint fork.
    - `initialize` advertises `sessionCapabilities.fork` as `{}`.
    - `session/prompt` and `session/fork` ignore `_meta.acpStack.messageId`, and a prompt response carries no `_meta`.
    - The adapter writes and reads no `<stem>.acp.json` file beside a session file.

## Compatibility

- A client that forked through `_meta.acpStack.messageId` moves to `session.cursors` and `cursorId`.
- Some live prompts get their cursor from the next `session/load`:
    - a session's first prompt
    - the first prompt after a `session/resume`
    - a prompt that follows a turn the client saw no message or tool call from
- `<stem>.acp.json` files left by earlier versions are unused and stay on disk, also after `session/delete`.
