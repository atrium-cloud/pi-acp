Initial release: an ACP v1 agent for Pi Agent over its RPC mode, for Pi 0.84.3 and above.

## Supported ACP v1 surface

Agent methods (client → adapter):

| Method | Notes |
| --- | --- |
| `initialize` | Protocol version 1; capabilities below; no auth methods (Pi resolves credentials from its own store and environment). |
| `session/new` | Spawns one `pi --mode rpc` subprocess at an absolute `cwd`; `mcpServers` are connected by the adapter's own MCP client; `additionalDirectories` are rejected. |
| `session/list` | Pi's own session store filtered by `cwd`, offset-paginated, newest first. |
| `session/resume` | Reopens a stored session without replaying its transcript. |
| `session/load` | Reopens and replays the transcript (user/agent/thought chunks, completed tool calls with diffs) before responding. |
| `session/fork` | Forks from the parent's last settled turn into a new session, optionally in another `cwd`. |
| `session/close`, `session/delete` | Close stops the subprocess; delete also removes the session file. |
| `session/set_config_option` | `model` (`provider/id`) and `thought_level`. |
| `session/prompt` | Text, image, and embedded-resource blocks; slash commands from the advertised list; `$/cancel_request` cancels the turn. |
| `session/cancel` | Aborts the turn; the prompt ends `cancelled`. |

Client methods (adapter → client): `session/update`, `session/request_permission` (mutating built-in tools and every MCP tool, fail-closed).

Session updates emitted: `agent_message_chunk`, `agent_thought_chunk`, `user_message_chunk`, `tool_call`, `tool_call_update` (with `rawInput`, `rawOutput`, `locations`, `diff` blocks for edits), `config_option_update`, `available_commands_update`, `session_info_update`, `usage_update`.

Capabilities advertised: `loadSession`; `sessionCapabilities.list/resume/fork/close/delete`; `promptCapabilities.image/embeddedContext`; `mcpCapabilities.http/sse`. Not advertised and not implemented: audio prompts, session modes, additional directories, breakpoint forks, fs/terminal proxying, steering. See docs/caveats.md.

## Runtime

- From a checkout, Pi Agent is a dependency of the package and is launched through its RPC entry under the current Node; the release bundle carries no `node_modules`, so it runs the `pi` named by `PI_ACP_PI_BIN`.
- Every RPC round-trip is bounded (`PI_ACP_RPC_TIMEOUT_MS`); a failed or never-started Pi turn is a protocol error, never a clean `end_turn`.
- Permissions and MCP are pi-acp's own Pi extensions, embedded in the bundle and loaded with `-e`; the user's own extensions keep loading.

## Distribution

One `pi-acp.zip` attached to the GitHub Release: the `pi-acp` executable (a bundled script that runs on the Node 22.19+ already required by Pi; on Windows invoke it as `node pi-acp`) with LICENSE and NOTICE. Set `PI_ACP_PI_BIN` to the `pi` executable of an installed Pi Agent. Not published to npm.
