A turn Pi reports as aborted ends `cancelled`. For Pi 1.1.0 and above.

## Changed

- A turn ends `cancelled` whenever Pi reports its run aborted, not only after a `session/cancel`.
    - Pi 1.1.0's `agent_settled` carries an `aborted` flag, which outranks the stop reason of the last assistant message.
    - It covers an abort the adapter did not send, such as one from an extension.
    - An abort that landed before the first assistant message or during a compaction left no `aborted` stop reason; prior releases reported such a turn as `end_turn` or an internal error.

## Compatibility

- Pi releases below 1.1.0 are not verified. The dependency floor moved to `>=1.1.0`, since the turn settlement reads `agent_settled.aborted`.
- Pi 1.0.1 and 1.1.0 change what a client sees through the adapter:
    - MCP tool names replace every character outside `[A-Za-z0-9_]` with `_`, so a server named `my-server` exposes `mcp__my_server__<tool>`.
    - `bash` output no longer carries ANSI fragments split across chunks.
    - The Azure provider is `azure`, renamed from `azure-openai-responses`; a `model` value naming the old provider no longer resolves.
