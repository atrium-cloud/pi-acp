Opt-in warm spare and idle teardown for Pi subprocesses, startup timing lines under `PI_TIMING=1`, a faster first session, and a turn Pi reports as aborted ends `cancelled`. For Pi 1.2.0 and above.

## Added

- `PI_ACP_WARM_SPARE_MAX_AGE_MS` keeps one Pi subprocess started ahead for the next `session/new`; off when unset.
    - A `session/new` with the same cwd and the same MCP servers, in the same order, takes it instead of starting Pi cold.
    - The spare is refilled once a prompt resolves, with that session's cwd and MCP servers, so its start never competes with a running turn.
    - Models and thinking levels are re-read at the take.
    - Pi's settings, `AGENTS.md`, skills and prompt templates are as Pi read them when the spare started.
    - A spare that reaches this age is stopped.
    - Until then it is one more Pi subprocess, about 120 MB resident, with its MCP servers connected.
- `PI_ACP_IDLE_TIMEOUT_MS` stops a session's Pi subprocess once the session has had no request in flight for this long; off when unset.
    - The next prompt, config change or `session/load` relaunches it on the same session.
    - The relaunch opens the session's file with `--session`, or its id with `--session-id` when Pi has not filed it yet.
    - A `session/resume` answers from what the adapter kept and relaunches nothing.
    - The model, thinking level and session name are re-applied where the woken Pi differs.
    - `allow_always` grants are kept.
    - The first request after idle pays a cold start.
    - While the subprocess is stopped, extension background work and MCP servers stop.
    - MCP servers reconnect on wake, and one that fails to connect is reported again.
    - Commands or options that changed meanwhile reach the client as `available_commands_update` or `config_option_update`.
- Both settings take whole milliseconds; a malformed value fails startup, as for `PI_ACP_RPC_TIMEOUT_MS`.
- With `PI_TIMING=1`, Pi's own startup profiling switch, the adapter logs the Pi launch to stderr.
    - It also logs a startup timing line for every Pi subprocess it starts, warm spares and wakes included, and for every warm spare take.
    - The line splits the spawn, Pi's readiness, the metadata reads and the total, with Pi's own timing blocks attached.
    - A take logs `mode:"take"` with the spare's age.

## Changed

- The permission gate is written as an `.mjs` module, which Pi imports natively.
    - The first session in each adapter process no longer pays Pi's TypeScript transform of the gate, about 220 ms.
- From a checkout, the bundled Pi launch sets `NODE_COMPILE_CACHE`, since Pi's RPC entry does not enable Node's compile cache itself.
    - A `PI_ACP_PI_BIN` launch is left to Pi's own cache.
- A turn ends `cancelled` whenever Pi reports its run aborted, not only after a `session/cancel`.
    - Pi 1.1.0's `agent_settled` carries an `aborted` flag, which outranks the stop reason of the last assistant message.
    - It covers an abort the adapter did not send, such as one from an extension.
    - An abort that landed before the first assistant message or during a compaction left no `aborted` stop reason.
    - Prior releases reported such a turn as `end_turn` or an internal error.

## Fixed

- A session an extension names before its first prompt keeps that name; prior releases replaced it with a title derived from the first prompt.

## Compatibility

- Pi releases below 1.2.0 are not verified; the dependency floor moved to `>=1.2.0`.
    - The turn settlement needs at least Pi 1.1.0, for `agent_settled.aborted`.
- Pi 1.0.1, 1.1.0 and 1.2.0 change what a client sees through the adapter:
    - MCP tool names replace every character outside `[A-Za-z0-9_]` with `_`, so a server named `my-server` exposes `mcp__my_server__<tool>`.
    - `bash` output no longer carries ANSI fragments split across chunks.
    - The Azure provider is `azure`, renamed from `azure-openai-responses`; a `model` value naming the old provider no longer resolves.
    - OpenRouter lists only the models the API key may use, and Pi saves that list for offline use.
- With `PI_ACP_WARM_SPARE_MAX_AGE_MS` and `PI_ACP_IDLE_TIMEOUT_MS` unset, sessions start and stop as in prior releases.
