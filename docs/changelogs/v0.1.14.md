A client that names its sessions itself can switch off the adapter's automatic session names. For Pi 1.5.0 and above.

## Added

- `PI_ACP_MANUAL_SESSION_TITLES`: set to `1`, the adapter names no session itself, and `session/list` reports an unnamed session's `title` as `null`. Unset or empty keeps the automatic name from the first line of the first prompt.
    - `/name <name>` and a Pi extension's `setSessionName` name a session in both modes, each sending `session_info_update`, and a wake gives the name back to the relaunched Pi.
    - A `_acpStack/launch_env` request sets it in `env` or removes it in `unset`; in neither, the start-time value stays.
    - Any other value stops the adapter at startup, and refuses a launch env request with `invalid_params` naming the variable, never its value.
