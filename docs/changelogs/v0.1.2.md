Shell tools as terminal entries: streamed output and parsed exit codes.

## Added

- Pi's shell tools (`bash`, `powershell`) render as ACP terminal entries. The `tool_call` is titled by the verbatim command and carries a `terminal` content item plus `_meta.terminal_info { terminal_id, cwd }`, with the terminal id equal to the tool call id and `cwd` the session cwd. This follows the Zed `_meta` convention rather than the `terminal/*` client methods, since Pi runs the command itself.
- Output streams while the command runs: each `tool_call_update` carries `_meta.terminal_output_delta` with the new tail of Pi's cumulative snapshot, ANSI intact. When Pi's accumulator drops scrolled-off lines and the snapshot no longer extends the previous one, `_meta.terminal_output` is sent instead as a full replace.
- The closing `tool_call_update` carries `_meta.terminal_output` (full snapshot) and `_meta.terminal_exit { terminal_id, exit_code, signal }`. Pi's appended `Command exited with code N` line is parsed into `exit_code` and stripped from the data; the `(no output)` placeholder becomes empty data; a failure without that line (denied, aborted, timed out) reports exit 1. `signal` is always null.
- `session/load` replays a completed shell call as the same terminal entry the live turn sent, rooted at the session cwd.

## Changed

- Shell progress and end updates carry no `content` blocks (`rawInput` and `rawOutput` are still sent), so the terminal item from the `tool_call` persists. Prior releases sent the output as text content blocks.

## Compatibility

- Terminal metadata is emitted unconditionally. A client that ignores `_meta` sees no shell output; it must implement `terminal_info`, `terminal_output_delta`, `terminal_output`, and `terminal_exit`. A client that skips deltas still converges on the closing `terminal_output` replace.
