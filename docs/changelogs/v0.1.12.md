A parent process can change provider credentials without restarting the adapter. For Pi 1.5.0 and above.

## Added

- The `_acpStack/launch_env` request, advertised as `agentCapabilities._meta.acpStack.launchEnv`. Its params `env`, `unset` and `hideProviders` are all required, each request replaces the whole state, and the answer is `{}`.
    - Every later Pi launch, a wake, the warm spare and the catalog refresh included, starts from the adapter's own env with each `unset` name removed and each `env` variable set.
    - `hideProviders` replaces the `PI_ACP_HIDE_PROVIDERS` list for every later model option.
    - Each session's Pi is stopped once no request is in flight, and its next request relaunches it on the new env. The warm spare is dropped.
    - A request matching the current state changes nothing, with `unset` and `hideProviders` compared as sets.
    - A malformed request is refused with `invalid_params` naming the key, never a value.
